Releasing Lootwright

How to put a new version on CurseForge yourself, from a finished change to a live file. Takes about ten minutes, most of it waiting for CurseForge.

  1. Check the version and changelog

    Open CHANGELOG.md. The top section should read ## 0.x.y, not released yet and list every change under New, Changed or Fixed, in words a player understands. Delete any empty heading.

    If the top section is an already released version, open a new one first:

    What changedCommand
    Only fixes, text or colour tweaks, a data rebuildbump patch (0.13.0 → 0.13.1)
    A new feature, command or option, or saved data changedbump minor (0.13.0 → 0.14.0)
    python -I tools/release.py bump patch

    Test it in game (/reload) and commit before you go on.

  2. Open PowerShell in the project folder

    cd "I:\VibeStuff\Wow addons\ItemFinder"

    On Bazzite use a terminal and python3 instead of python:

    cd "/var/mnt/I/VibeStuff/Wow addons/ItemFinder"

  3. Build the zip

    python -I tools/release.py

    This fetches players' shared loot from GitHub (with gh; if that fails it uses the last fetched copy), rebuilds the data, makes dist\Lootwright-0.x.y.zip, checks that all version numbers match, and copies the changelog to your clipboard, ready to paste. It also saves it as dist\changelog-0.x.y.md.

    Copied something else since? Put the changelog back on the clipboard with:

    python -I tools/release.py notes

  4. Upload on CurseForge

    • Go to authors.curseforge.com → Lootwright → Files and press Add File.
    • Upload file: Choose File → dist\Lootwright-0.x.y.zip.
    • Display name: Lootwright 0.x.y (it starts as the zip's file name).
    • Release options: leave "Publish this file automatically once approved".
    • Game version: 1.60.1 (copied from the last file; change it when Forever updates).
    • Release type: Release. Never Beta: Beta files are hidden in the CurseForge app.
    • Changelog: switch the dropdown above the box from WYSIWYG to Markdown, click in the box and press Ctrl+V.
    • Related projects: QuestieDB should show as Required Dependency (from the default relations). Leave it.
    • Press Add File.

    The Files tab then shows the new row: Uploading → Processing → Under Review → Approved. Review usually takes from a few minutes to a few hours.

    Check it went in. Once the upload failed to save without an error. If the new version isn't on the Files tab, upload it again.

  5. Mark it released and push

    This dates the top changelog section:

    python -I tools/release.py released
    git commit -am "0.x.y released"
    git push

    Replace 0.x.y with the version number.

  6. Update the pinned pages

    Ask Claude in any Lootwright chat: "0.x.y is released, update the changelog and phase pages." That republishes the changelog page, the phase summary and the notes in CLAUDE.md.

When to update the CurseForge page too

  • Description: Description tab, Markdown editor, Save. The inline images load from GitHub (docs/curseforge/screens/), so replace a picture by pushing a new file with the same name.
  • Gallery: Media tab → Add media. Images must be under 850 px wide. Hover a picture for the edit (title, description, star = featured) and delete buttons.

If something goes wrong

  • "Core.lua says … but the TOCs say …": run bump again with the version you want; it sets all of them.
  • "CHANGELOG.md has no section for …": add a ## 0.x.y, not released yet section at the top.
  • "No clipboard tool found": open dist\changelog-0.x.y.md and copy from there.
  • A Lua error after release: fix it, bump patch, and release again. CurseForge keeps every older file.
